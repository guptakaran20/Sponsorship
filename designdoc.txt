
# 🏗️ SYSTEM DESIGN DOCUMENT

## Product: **SponsorBridge**

---

## 1. 🧭 High Level Architecture

We are building a **Two-Sided Marketplace Platform**

So architecture must support:

* Clubs
* Companies
* Event Listings
* Sponsorship Deals
* Messaging
* Payments
* Analytics

---

### 🔷 Architecture Type → **3 Tier Architecture**

```
Frontend  →  Backend API  →  Database
                ↓
        External Services
```

---

## 2. 🧱 Major Components

| Layer          | Components                  |
| -------------- | --------------------------- |
| Client Layer   | Web App (Clubs & Companies) |
| API Layer      | Auth Service, Event Service |
| Business Logic | Matching Engine             |
| Communication  | Chat Service                |
| Storage        | DB + File Storage           |           
| Analytics      | ROI Tracking                |
| Admin Panel    | Verification System         |

---

## 3. 🔁 System Workflow

### 🏫 Club Side

1. Club registers
2. Verified using college email
3. Creates Event Listing
4. Uploads Sponsorship Deck
5. Defines Sponsorship Tiers
6. Event visible in Marketplace

---

### 🏢 Company Side

1. Company registers
2. Sets:

   * Budget
   * Target audience
   * Event type preference
3. Gets matched with events
4. Sends Sponsorship Request
5. Chat opens with Club

---

### 🤝 Deal Flow

```
Company Applies
      ↓
Negotiation Chat
      ↓
Event Happens
```

## 5. 🧠 Matching Engine (Recommendation Logic)

Match companies with events based on:

```
Event Type == Preferred Event
Budget >= Sponsorship Tier
Location Match
Target Audience Match
```

Later:

* Use ML-based recommendation model
